# P0 · 温暖主题层（设计系统地基）设计文档

> 日期：2026-07-15
> 状态：设计已确认，待写实现计划
> 所属大项目：**登录后用户前端重构**（拆解为 P0–P3，本文件是 P0）

## 背景与动机

SillyTavernMOD 是一个面向多用户的托管式 SillyTavern 服务（注册 / 邀请码 / 论坛 / 存储配额 / 公共角色库）。目标用户**以新手为主，同时保留高级用户的完整能力**，视觉方向为**温暖治愈、亲和**。

用户反馈：登录后的核心界面「几乎全是繁琐的设置界面」，不友好。实测核心 App（`public/index.html`）确有约 **686 个控件**（105 滑块 / 171 复选框 / 130 下拉 / 280 文本输入）分布在 **9 个顶部抽屉**中，新用户落地即被淹没。

### 关键约束：上游可合并性

本项目是**上游追踪型 fork**，架构刻意保持与官方 SillyTavern 可合并（见 `MODIFICATIONS.md`：核心改动仅集中在 1 个文件的 6 个钩子，其余以 sidecar 模块隔离）。因此前端改造必须是**叠加式**（扩展 + CSS + 主题），**严禁重写 `index.html`**，否则每次上游合并都会被破坏。

### 大项目拆解（P0–P3）

「登录后体验」拆成 4 个可独立交付的子项目，每个独立 spec → 计划 → 实现：

- **P0 温暖主题层（本文件）** — 纯外观换肤 + 设计 token 地基。解决痛点「旧/乱/不温馨」。
- **P2 抽屉分级 + 简单/进阶模式** — 收起高级抽屉与冷门小节。解决「抽屉太多、面板太密」。
- **P1 落地首页 + 新手引导** — 登录后温暖 home + 首登引导。解决「一登录就懵」。
- **P3 账户 &「我的账户」/管理面板重设计** — 统一 `stc-admin-panel` 到新设计系统。

> 注：登录页 / 欢迎页 / 注册页**维持现状**（现有暗色二次元风 + 视频背景，用户明确表示保留），不在本次范围内。

排序：**P0 → P2 → P1 → P3**。P0 是地基、零功能风险、见效最快，且产出 P1–P3 复用的设计 token。

## P0 目标与范围

把核心 App 换成温暖治愈的默认外观，**只动外观**（配色 / 间距 / 圆角 / 字体节奏），并沉淀 P1–P3 复用的**设计 token**。

**做：**
- 暖色主题（深浅两套），更柔和的圆角与留白，亲和排版，温暖强调色。
- 一组 `--stc-*` 设计 token（P1–P3 复用）。

**不做（明确排除，留给后续子项目）：**
- 隐藏任何抽屉或设置（→ P2）
- 落地首页 / 引导（→ P1）
- 账户 / 管理面板（→ P3）
- `index.html` 结构或 DOM 改动
- 任何功能 / 逻辑改动

## 架构与交付机制

SillyTavern 原生主题系统：主题是 JSON 文件（`default/content/themes/*.json`），字段映射到 `--SmartTheme*` CSS 变量，并含一个 **`custom_css` 字段**可携带任意结构/间距 CSS。因此**单个主题文件可同时交付「配色 + 结构润色」**，100% 上游原生、可合并。

**交付物：**

1. `default/content/themes/暖阳拿铁.json`（浅色，**默认**）
2. `default/content/themes/暖夜可可.json`（深色，可切换）
3. 在 `default/content/index.json` 注册这两个主题（`{filename:"themes/…", type:"theme"}`），ST 首次运行会把它们拷进每个用户的主题列表。
4. 通过 MOD `src/stc-mod/services/default-template.js`（新用户配置模板，MOD 自有钩子）把新用户默认激活主题设为「暖阳拿铁」，**不改上游默认**。
5. 设计 token：作为主题 `custom_css` 里的 `--stc-*` CSS 变量输出，P1–P3 直接引用。

**为何选主题 JSON 而非全局注入 CSS：**
- 主题 JSON 是 ST 原生机制，用户仍可自由切换/自定义，不与用户主题选择打架。
- `custom_css` 已能承载结构润色，无需额外全局样式表。
- 完全避免触碰 `index.html`。

## 设计 Token（色板）

主题 `custom_css` 顶部用 `:root` 定义 `--stc-*`，并覆盖对应 `--SmartTheme*`。深浅两套**共用同一批 token 名，只换值**，保证 P1–P3 引用一致。

### 暖阳拿铁（浅色 · 默认）

| Token | 值 | 用途 |
|---|---|---|
| `--stc-bg` | `#F7EFE4 → #F1E3D2`（线性渐变 160deg） | App 背景 |
| `--stc-surface` | `#FFFFFF` | 面板 / 角色气泡 |
| `--stc-surface-2` | `#FBF4EA` | 抽屉栏 / 顶栏 |
| `--stc-text` | `#4A3F35` | 正文（暖棕） |
| `--stc-text-muted` | `#9B8B7A` | 次要文字 / 占位符 |
| `--stc-accent` | `#E0895D` | 主强调（珊瑚桃）· 按钮 / 激活态 |
| `--stc-accent-hover` | `#D4784B` | 悬停 |
| `--stc-accent-soft` | `#FBE7D6` | 用户气泡 / 柔和高亮 |
| `--stc-border` | `#EBDDCB` | 分隔线 / 描边 |
| `--stc-radius` | `14px` | 默认圆角 |
| `--stc-radius-sm` | `10px` | 小圆角（图标块等） |
| `--stc-radius-lg` | `20px` | 大圆角（面板 / 卡片） |

映射到 ST 原生字段（示例）：`main_text_color=#4A3F35`、`blur_tint_color≈#FBF4EA`、`user_mes_blur_tint_color≈#FBE7D6`、`bot_mes_blur_tint_color=#FFFFFF`、`border_color=#EBDDCB`、`quote_text_color`/`italics_text_color`/`underline_text_color` 用暖色变体、`shadow_color` 用低透明暖阴影、`blur_strength` 适度、`font_scale=1`。

### 排版 / 动效
- **不引入新字体 / 外链资源**（沿用本地 Noto Sans，符合 MOD 减少外部请求的目标）。
- `custom_css` 仅微调 `line-height` 与气泡/面板内边距，增加呼吸感。
- 尊重 `prefers-reduced-motion`：减少/关闭非必要过渡。

## 结构润色范围（全部在 `custom_css` 内，非破坏性）

只做「让密变得不那么密」的视觉层，**不删不藏任何功能**：

- 面板 / 气泡 / 输入框统一柔和圆角 + 更足内边距。
- 抽屉背景改用 `--stc-surface-2`，硬分隔线换成 `--stc-border` 柔线。
- 主按钮 / 激活抽屉图标用暖强调色；非激活项**降透明度弱化**（而非隐藏）。
- 滑块 / 开关 / 下拉沿用原生 DOM 结构，仅套暖色，不改结构。

**护栏：**
- 优先用变量覆盖，尽量少用深层选择器（抗上游漂移）。
- 结构选择器最小化 + 注释；即便失效也只掉「润色」，不影响功能与可读性。
- 不覆盖用户已有自定义（仅对新用户设默认）。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 上游改选择器 / 类名 → `custom_css` 结构规则失效 | 优先变量覆盖；结构选择器最少化并注释；失效只掉润色不影响功能 |
| 老用户已自选主题被强改 | 只对**新用户**设默认；不覆盖已有 `power_user.theme`；老用户可在下拉自选 |
| 浅色底对比度不足 | 正文/背景守 WCAG AA（`#4A3F35` on `#F7EFE4` ≈ 8:1，达标）；强调色不用于正文 |
| 深浅两套色值漂移不一致 | 两套共用同一批 `--stc-*` token 名，只换值 |
| 引入外部资源拖慢加载 | 不引新字体 / 外链，沿用本地 Noto Sans |

## 验证方式

1. 启动应用 → 新建测试用户 → 确认默认即「暖阳拿铁」，主流界面（聊天 / 抽屉 / 输入框 / 角色管理）观感温暖、无错乱。
2. 主题下拉切「暖夜可可」→ 深色正常、可读。
3. 用 Playwright / 浏览器实际驱动：逐个打开抽屉截图，肉眼核对无破版、对比度可读。
4. 确认老用户已有主题不被改动。

## 成功标准

- 新用户登录后核心界面默认呈现温暖治愈观感，功能零缺失。
- 两套主题可自由切换、均可读、对比度达标。
- 无 `index.html` 改动；主题以纯 JSON + `custom_css` 交付。
- 产出 `--stc-*` token，可被 P1–P3 直接引用。
